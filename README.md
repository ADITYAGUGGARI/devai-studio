# DevAI Studio

Research AI developments for software engineers, turn verified sources into original Instagram carousels, and review every post before publication.

The project contains a FastAPI API, a React dashboard, and an Expo native editorial app. It supports daily primary-source discovery, source-grounded 6–8-slide draft generation, editing, approval, and 1080 × 1350 PNG export. Every generated post remains a draft until a person reviews and approves it.

## Run locally

Use Python 3.13 and Node 22 (`nvm use` if you use nvm). Python 3.12+ is supported by the package. Local development uses PostgreSQL in Docker. Real generation requires a server-side AI key; Instagram credentials are needed only for publishing. [Local startup and verification](docs/LOCAL_STARTUP.md) documents accounts, migrations, backups and native testing.

From the repository root:

```bash
cp .env.example .env
cp web/.env.example web/.env
cp mobile/.env.example mobile/.env
make setup
# Set ADMIN_PASSWORD in .env first.
docker compose up -d postgres
make migrate
```

Run each service in its own terminal:

```bash
make dev-api
make dev-web
```

Open the dashboard at <http://localhost:5173> and API documentation at <http://localhost:8000/docs>. **Refresh research** fills the persistent topic queue. Sign in, review and approve a source, select its priority/category and eight slides, then generate original copy and complete AI-native images in the background. Add `OPENAI_API_KEY` in the root `.env` for generation and validation. Manual excerpts can be added to the queue and explicitly verified before generation. The API worker runs by default; jobs remain visible after browser refresh and support retries and individual slide regeneration.

Every slide’s full composition, including lettering, is generated by the image model. No local text overlays or preset layouts are used. Image processing is limited to validation, resizing, conversion and export. A vision model checks visible text and legibility; a reviewer must still inspect every image and source before approving. ZIP exports include PNGs, caption, source evidence and review metadata. Older overlay-based images are preserved but must be regenerated before approval/export as current native compositions.

Publishing is available from an approved editor after configuring Instagram credentials and a public HTTPS media origin. The server publishes immutable JPEGs belonging to that approved version. See [workflow setup and operations](docs/workflow.md) for complete configuration, job behavior, validation limits and Meta reconciliation.

Sign in with the workspace account created from `ADMIN_EMAIL` and `ADMIN_PASSWORD` at first startup. Accounts use server-managed sessions and roles. Provider secrets stay on the backend; never place them in public client environment values.

For mobile, run `make dev-mobile` and sign in with the same workspace account. A physical device needs `EXPO_PUBLIC_API_URL` set to your computer's LAN address and the API listening on that interface. Xcode 27 uses **Device Hub** to display simulator screens. See [local startup](docs/LOCAL_STARTUP.md) and [focused UX design](docs/UX_DESIGN.md) for navigation and Expo Go setup.

## Docker development

```bash
docker compose up --build
```

The same web/API URLs apply. PostgreSQL is available on loopback port 5433 by default to avoid competing with other local projects. Compose waits for database/API health before starting dependent services. This is a development setup, including the Vite dev server and local database password.

## Background jobs and daily research

The API processes durable jobs with `BACKGROUND_WORKER_ENABLED=true` by default. For a dedicated worker, disable that setting in the API and run `make worker` against the same database and asset directories.

Daily scheduling is disabled by default. Set `DAILY_ENABLED=true` in the server `.env` and restart the API/worker, or explicitly run:

```bash
make scheduler
# Docker scheduling:
docker compose --profile automation up --build
# Additional standalone workers (shared asset volumes):
docker compose --profile workers up --build
```

At or after `DAILY_HOUR` (8 AM by default) in `DAILY_TIMEZONE`, a date-deduplicated job refreshes official feeds, queues readable recent source evidence and leaves topic selection to the reviewer. Set `DAILY_GENERATE_CAROUSEL=true` only if you want an automatic daily draft with complete validated images. No automatic publication follows. The dashboard’s daily and additional-story buttons use the same background job system. Keep the application/worker running; these commands do not install an OS service or configure a ChatGPT automation.

## Quality checks

```bash
make check          # Tests, lint/format checks, client type checks, web build
make test           # API and service tests only
make format         # Apply Ruff and Prettier formatting
npx playwright install chromium
npm run test:e2e    # Browser regression tests; all APIs mocked
```

CI runs equivalent checks on pushes and pull requests. Each HTTP test gets its own in-memory database. Tests use fake provider responses and do not publish to Instagram or spend AI credits. npm lockfiles and `api/constraints.txt` capture resolved dependencies; update them deliberately.

## Current limits and next work

Official-source identity, AI grounding and vision checks cannot establish every fact or catch every image error. Human approval is enforced. External creator originality, real image quality, multi-day operations and live Meta publishing still need verification. Public deployment also needs account authentication, migration operations, backup/monitoring and asset lifecycle controls. Native mobile packaging and an inherited Expo dependency upgrade remain outstanding.
