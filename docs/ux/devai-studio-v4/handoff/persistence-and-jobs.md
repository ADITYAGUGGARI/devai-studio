# Persistence, autosave and recovery

Autosave: local buffer on each input, debounce 800ms of inactivity, flush on valid blur and explicit Save; per-output sequential queue prevents out-of-order writes. Only fields that changed are sent. Persist buffer in IndexedDB web / protected native file store scoped account+workspace+entity+baseRevision. Encrypt/protect native data and do not cache credentials; auth tokens Keychain. Server ACK returns revision; status becomes Saved only then. Invalid draft input stays local with inline error until corrected; no silent truncation. At 5sec unsaved delay show unsaved state; network failure persistent save_failed. Head/slide switching does not clear another slide's buffer. Jotai holds local selection/buffers, query layer server cache; Python/PostgreSQL authoritative.

Conflict: retain base snapshot, local diff, current server snapshot. Automatically merge only disjoint fields against fresh revision; same-field conflicts open Mine/Server/manual merge sheet. Choosing Mine is an explicit new CAS write. If it conflicts again refresh comparison, never force. Source or asset version conflicts discard stale provider result from current head but keep history for diagnostics. Undo after ACK is a new revision, approval invalidating; redo invalidated by new branch. Restore is copy-forward, not rewind of audit.

Cross-device: foreground/reconnect/reload fetch session/workspace then entity and job revisions; show reconnect status until authoritative read. Query active jobs every 2s visible, normal lists 15s or invalidation events; background web slows polling; iOS foreground refresh, push only hint, optional OS refresh never required for correctness. Backend continues even with both clients closed only while worker infrastructure is running. Progress describes real stage and units, not fabricated 45%. Last heartbeat requires new public field; existing API has no reliable stalled indicator.

Server operations: immutable committed asset per unit; recover lease and reuse only validated hash-matching units. Existing transient 429/5xx/transport retry at 30/60sec up to 3 attempts preserved. Key/billing/unsupported/grounding error needs user correction. Manual retry must expose potential additional paid calls; a provider call may have succeeded before local persistence. Cancellation cooperative at safe checkpoint; partial committed units preserved, active call may incur charges. Generation locks affected output; other output editable independently after new model migration. Publication has max one final-call attempt and no automatic blind retry.

Unknown HTTP outcome: retain action key, lookup server result before resubmission; paid generation and publication never queued from offline cache. Approval/sign-out/access changes do not delete unacknowledged work silently. Sign-out offers save or local text export; public shared-device signout clears cached sensitive content after explicit handling. Jobs/schedules are server authorization, not device timers. Browser beforeunload only native generic warning when local unacknowledged buffer remains; in-app navigation uses D-UNSAVED.

Asset lifecycle: previous images/audio/video kept in immutable version history; orphan cleanup only after no approval/publication/export reference and policy retention. Trash 30 days; pending publication unknown blocks purge. Exports signed/expiring and revocable; physical export on user device is no longer centrally revocable. No raw secrets or API keys in ZIP, audit, diagnostics or analytics reports. Backup/restore and production migrations belong to implementation readiness gates, not claims established by UX files.
