# Persisted content outputs

Revision4 implementation is ongoing. This documents actual current code, not complete acceptance of the design package.

## Creation and jobs

Web `/create` and native Content → Create content require a topic whose readable evidence has been explicitly verified and approved. `/v1/setups` saves selected formats and editorial settings; revisioned edits use `expectedRevision` and `Idempotency-Key`. `/v1/setups/{id}/generate` confirms the exact saved formats, provider-capability revision and maximum provider-request budget. Each selected output has its own document and durable `studio_output` job. No browser or iOS foreground process is needed to continue server work.

Provider availability reports configuration and codec dependencies; it never claims a key was live-tested merely because one is present. Request budgets count actual attempted JSON/image/vision/speech provider calls, including failures, and are debited persistently before network submission. They are not dollar estimates. Existing usage records capture actual response usage where supplied. Budget exhaustion prevents further provider calls; authorizing additional work is an explicit action. Restoring an old revision does not restore an old budget.

Carousel creation extends the existing source-grounded writer, individual complete-image AI generation, visual validation, regeneration and legacy carousel editor. Saved audience/tone/language are sent to the writer. No template or programmatic artwork composition is used. New independent output review requires synchronization when the existing carousel editor changes its version/caption.

Reel creation writes a grounded 5–7scene script, validates source claims, generates complete AI-composed 9:16 scene images, audits readable visible text, generates real per-scene WAV narration, aligns narration to scene duration, renders a30–40second1080×1920H.264/AAC MP4 and fully decodes the result. Explicitly selecting no narration produces a silent Reel; a failed configured speech request is never replaced by silence. Narration that requires more than1.25× tempo adjustment fails with scene-specific recovery rather than silently truncating it. Subtitles are generated from the scene script and burned with FFmpeg/libass. Scene collections/storyboards are not labeled completed videos.

Image-generation model defaults are preserved as `gpt-image-2`; carousel requests use `OPENAI_IMAGE_SIZE` (default1088×1360), Reel scenes request1152×2048 and normalize the AI image to1080×1920. Resizing/conversion/validation are permitted programmatic processing; the entire scene artwork composition is generated by the model. See official [image documentation](https://developers.openai.com/api/docs/guides/image-generation) and [speech documentation](https://developers.openai.com/api/docs/guides/text-to-speech).

## Editing, assets and review

`/v1/outputs/{id}/timeline` uses optimistic concurrency, retained stable scene identifiers and immutable revision history. Web and native use800ms autosave, retain competing local edits and expose conflict resolution. Scene editing/reordering and individual generation preserve earlier successful images, audio and renders. A changed timeline retains the previous MP4 while marking it stale; export/review require a current, validated render and supported grounding. Source citations cannot be removed from the caption.

Private media is stored below `STUDIO_MEDIA_DIR` and indexed by asset documents containing SHA256, kind and validation metadata. API responses remove server paths. Authenticated `/v1/assets/{id}` validates availability/hash, supports Range requests, and respects existing workspace scoping. The API and every worker must share the same persistent media storage. Docker Compose now shares the `studio_media` volume in addition to preserved carousel/publishing volumes. Back up database and media together.

`/v1/outputs/{id}/review/submit` and `/review/approve` inspect sources, claims, assets and caption separately. The approval binds exact asset hashes, caption and source/timeline to an output revision. Reel and carousel approval are independent. Editing/regeneration/restoration clears the affected approval. `/changes` stores revision-request notes. Approval does not publish content.

`/versions` lists immutable revisions; `/versions/restore` creates a new Reel draft revision, clears approval, preserves current usage/budget and revision-request history, and refuses a stale evidence packet or active worker. Carousel restore continues through its existing editor. `/export` creates an actual ZIP of validated assets, caption and editorial metadata; missing/stale media fails with recovery rather than creating an empty success file.

## Runtime and verification

Configure server-only `OPENAI_API_KEY`, preserved JSON/vision/image models and optional `OPENAI_SPEECH_MODEL` (default`gpt-4o-mini-tts`). Configure `STUDIO_MEDIA_DIR`; ensure all workers see it. Install FFmpeg/ffprobe including libass, H.264 encoder and AAC support. Docker's API/worker image includes these dependencies. Some standalone macOS FFmpeg builds lack subtitles; preflight reports this and refuses subtitle rendering until the documented worker dependency is available. No browser/native bundle receives provider secrets.

Run real-codec isolated acceptance:

```sh
PYTHONPATH=api/src .venv/bin/python scripts/verify_reel_media.py
E2E_REEL_FIXTURE=true PLAYWRIGHT_CHROMIUM_CHANNEL=chrome npm run test:e2e:connected -- content-studio.spec.ts
```

These tests explicitly generate synthetic input only inside test environments and perform actual production FFmpeg rendering/decoding. They do not establish live AI generation. Set `FFMPEG_BIN`/`FFPROBE_BIN` when codecs are not on PATH. The native acceptance flow is `mobile/.maestro/v4-content-reel-expo.yaml`; run it with the isolated API8124 (`E2E_REEL_FIXTURE=true`) and Metro8086. Do not run the connected browser API on the same port simultaneously.
