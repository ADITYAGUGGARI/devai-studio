# Product requirements

## Audience and outcome

Prepare daily informational Instagram content for software engineers interested in AI. Explain what changed, why it matters technically, and how developers can use it. Target approximately 8 AM America/Chicago, with review before publishing.

## Coverage

Include AI news and model releases; coding agents and developer tools; Python/backend tutorials; RAG, agents, MCP, evaluation, and architecture; AI for testing, DevOps, security, and production; and advanced concepts with practical examples.

Suggested mix from the brief:

| Category                                | Share |
| --------------------------------------- | ----- |
| News with engineering analysis          | 30%   |
| Hands-on tutorials and code             | 25%   |
| Architecture and production engineering | 20%   |
| Tool comparisons and trade-offs         | 15%   |
| Original engineering insights           | 10%   |

This is a target over time, not a reason to invent daily news.

## Daily package

Deliver 6–8 slides at 1080 × 1350 with a hook, verified explanation, developer implications, original example or diagram, limitations, and actionable takeaway. Include a caption, hashtags, sources, image files, and verification notes. The current generator produces exactly eight slides.

## Originality and trust

- Track prior topics, angles, sources, examples, and publication history.
- Inspect similar public material when accessible; do not claim exhaustive Instagram search.
- Write original explanations and examples, using articles as attributed factual sources.
- Separate factual claims from analysis and verify examples before review.
- Revise similar drafts. Topic overlap around public news is expected.
- Use the creator's real engineering experience only when supplied or authorized; never invent personal experience.

## Next milestone acceptance

One scheduled run produces one source-linked, original, fact-checkable draft with rendered slides, caption, hashtags, and a history entry. Re-running it must not duplicate the package. Failed feeds or generation yield actionable errors and never fabricated news. Review remains required; scheduling and publishing are separate steps.
